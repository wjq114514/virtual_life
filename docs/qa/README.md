# docs/qa/ — 验证与缺陷报告

本目录存放端到端验证报告、缺陷修复报告和回归测试记录。
设计文档、协议契约、架构说明仍然放在 `docs/` 根下。

## 命名规范

```
<范围>-<内容>-<YYYYMMDD>.md
```

- **范围**：报告覆盖的子系统，用短横线连接的小写英文
  - `e2e-webui` — WebUI 浏览器端到端
  - `e2e-full` — 全链路（API + 客户端）
  - `e2e-system-node` — 系统节点客户端
  - `defect-fix` — 缺陷修复（跨子系统）
  - `android` — Android 客户端
  - `memory` — 记忆子系统
- **内容**：报告的性质，通常是一个词
  - `verification` — 验证通过记录
  - `fix` — 缺陷修复报告
  - `regression` — 回归测试
  - `triage` — 问题分类与定位
- **日期**：报告完成日期，`YYYYMMDD`，便于排序

示例：

| 文件 | 含义 |
|---|---|
| `defect-fix-20261023.md` | 10 月 23 日的缺陷修复报告 |
| `e2e-webui-verification-20261023.md` | 同日 WebUI 端到端验证 |
| `android-compilation-20261023.md` | Android 编译验证 |
| `memory-live-test-20261024.md` | 次日记忆子系统实测 |

同一天的多份报告按此规则自然排序；如果一天内有多轮，在日期后追加轮次：
`e2e-webui-verification-20261023-r2.md`。

## 报告结构

每份报告建议包含：

1. **环境** — 运行时地址、模型、关键配置
2. **改动清单** — 涉及的文件和改动摘要
3. **问题与修复** — 每个问题：根因 → 修复 → 验证
4. **验证结果** — 测试命令和通过/失败计数
5. **遗留问题** — 本次未改但值得关注的项

历史报告不做回写；后续报告引用旧报告的文件名即可。
