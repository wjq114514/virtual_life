# WebUI 工作台重构

目标是让现有运行时功能适合日常使用：先完成连接和伙伴选择，再进入对话；人格、共同经历、记忆管理与执行日志拥有各自清晰的工作区。

## 布局与交互

- 左侧导航保留伙伴选择与创建，提供对话、人格、日子、记忆、记忆日志五个入口；窄屏使用底部导航。
- 顶栏显示当前工作区，连接凭据在独立连接对话框中输入；伙伴状态位于右侧，窄屏按需打开抽屉。
- 对话以消息和输入区为中心。设备接入状态始终可见，预算、提示、单轮诊断、导出和手动记忆按需展开。
- 人格按定义、特征、表达与短期状态分组；记忆按记录、召回、积累、向量索引和关系知识分组。
- 使用同源静态资源、系统字体与内联图标，无前端安装步骤、外部 CDN 或字体请求。
- 各工作区支持 URL hash；前进、后退与切页保留当前页面内的对话和草稿。

## 功能与安全边界

本次只改变 WebUI 的呈现与交互，不改变 HTTP 合同。原有控制项和功能全部保留，包括情感解释与澄清、角色卡导入、人格版本检查、记忆更正与删除、图谱别名、日志游标分页及事件导出。

连接令牌只在页面内存中保留，只有设备关联所需的浏览器身份持久化。选择伙伴保持只读，显式接入才申请设备访问；设备、访问、epoch、租约与生成版本的输出复核继续生效。未决命令通过原回执恢复，不自动重发。所有用户或服务端文本安全渲染。

后端已有的注意力采集、自触发执行、系统采集器和原生宿主能力继续遵循各自合同；此次不在浏览器伪造设备观测或主动消息的输出权。

## 验收

在临时 SQLite、随机本地端口与确定性模型上运行真实 Chromium，检查关键管理操作、设备复用、未决回执、键盘与焦点、导航、桌面及移动端布局。截图和结构化检查报告由 `examples/webui_smoke.py` 输出。静态资源另检查 ID 保留、JavaScript 语法、资源打包和后端回归。真实模型质量、互联网部署、原生设备和多用户隔离不属于浏览器检查的结论。
