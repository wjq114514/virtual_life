# 非视觉自触发与情感系统：调研与演进草案

后续实现：[注意力边界与自触发](proactivity.md) 已交付宿主信号到参与决策、生成与输出复核的第一条闭环；[情感第二阶段](emotion.md) 已交付六维规则评价、三类可追溯纠错和分维度确定性恢复。实际协议以实现文档为准。额外采集通道、数据标定投影、OU/Kalman 动力学及长期关系仍是草案。

2026-10-15 实施取舍：方向澄清仅撤去原解释，不自动改变符号；强度纠错累计缩小，归因纠错保持效价。默认各维度仍使用原来的半衰期，只有显式配置才改变恢复参数。本文后续研究建议不代表均已实现。

调研日期：2026-10-14。本文是 [屏幕感知与心流判定](screen-perception-and-flow.md) 的补充，把视线从像素移开，讨论两件事：在没有屏幕感知的前提下她凭什么主动开口，以及现有的连续情绪台账怎么往前走一格。仍然只是调研与接口草案，没有修改运行时代码、没有跑测试、没有采集任何真实数据。

两个结论先说，它们决定了整份文档的形状。

**沉默必须是一等公民动作，而不是阈值以下什么都不做。** 混合主动式界面的原始框架就是三档：静默、问、做。延迟本身就是一次有代价或有收益的动作，实证显示几分钟的延迟几乎不产生成本，而打断会显著抬高压力却不降低产出。只写一个“超过阈值才说话”的实现，最后一定会退化成通知流。

**情绪应该被建模为状态变量，不是标签。** 现有的连续三维加指数衰减是这个方向的正确起点；下一步不是加一个“识别用户是悲伤还是愤怒”的分类器——那类分类器在公开基准上从 27 类塌缩到 4 类只换来 F1 从 0.46 到 0.69，稀有情绪甚至是 0——而是把“评价”作为中间层插在事件与三维之间，让每一次情绪变化都留下可校准的中间量。

## 参考与取舍

三条取舍贯穿全文。

**事实优先于推断。** 构建失败、命令退出码、日历忙闲、锁屏状态是环境给出的事实；“他在写代码”“他卡住了”是推断。同等重要度下永远选事实，因为事实不需要校准，也不会反向伤害用户。这一条同时意味着自触发的正当性主要来自“用户遇到了一个真实的阻塞”，而不是“我们觉得他现在需要帮助”。

**个性化优先于通用模型。** 从设备轨迹推断可打断性的公开研究里，个体化模型准确率明显高于通用模型（75.7% 对 69.8%），而活动**类型**分类只有约 61%。也就是说“是否刚切换过任务”可用，“在做什么类型”只能用来降权，不足以驱动开口。所有阈值都必须按个人滚动分布归一化。

**证据强度决定工程权重。** 本文把来源分成三档：多研究一致或元分析（可作设计依据）、单实验室或小样本（只作方向）、预印本（只作背景）。凡属后两档都会在正文里标出。另外，自触发与情绪两条线上有若干被广泛转引但查无实据的文献，本文只使用已核实的一手来源，并修正了几处常见误引。

## 非视觉通道分级

把通道按“它是事实还是推断”分成四档，这比按“平台/权限”分更适合决定自触发权限。

| 级别 | 定义 | 允许的自触发 | 本项目已有的或易得的通道 |
| --- | --- | --- | --- |
| A 事实 | 系统直接给出的状态，不含推断 | 可以请求注意 | 构建/测试失败、终端退出码、日历忙闲、低电量与热状态、屏幕解锁、锁屏与空闲、用户明确按下语音输入键 |
| B 强推断 | 多条独立证据一致，误报代价低 | 只允许非阻塞提示，可延迟生效 | 会议应用活跃加通话音频模式、连续多次构建失败加输入停顿抬升加无窗口切换、通知积压加长时间无切换 |
| C 软推断 | 单通道或弱信号 | 只写入台账，不主动触发 | 按键停顿分布变长、退格率抬升、输入密度下降、环境噪声抬升、语音唤醒强度变化 |
| D 背景先验 | 时段、星期、历史节律 | 只调阈值，永不单独触发 | 本地时刻、上次活跃时间、会话间隔、时段活跃分布 |

跨级别规则两条：任何 B 级触发要允许打断式提醒，必须在最近窗口内至少伴随一个 A 级事实；所有被抑制的候选都要落库，后面自触发一节会解释为什么。

### 音频是性价比最高的非视觉通道

大部分想回答的问题都不需要语音识别、不需要说话人分离、也不需要离开设备。

| 平台 | 系统播放音 | 麦克风 | 用户动作 |
| --- | --- | --- | --- |
| 安卓 | `AudioPlaybackCaptureConfiguration`（API 29 起）必须搭配 `MediaProjection` 与 `mediaProjection` 类型前台服务，只覆盖媒体类音频属性 | `AudioRecord` + `RECORD_AUDIO` + 麦克风类型前台服务 | 播放音需系统投屏授权；麦克风需运行时权限 |
| macOS | ScreenCaptureKit 的音频必须绑定一个屏幕捕获目标，可按应用排除 | `AVAudioEngine` | 投屏授权 + 麦克风用途说明 |
| Windows | WASAPI 环回 + 峰值表，无权限模型 | 采集端点 | 无系统权限 |
| Linux | PipeWire/PulseAudio 的 monitor 源，或 Portal + PipeWire | 采集流 | Wayland 需门户对话框 |
| iOS | 无公开的系统播放音接口 | `AVAudioEngine` | 麦克风用途说明 |

三个工程结论。**麦克风检测到人声不能证明用户主动发起对话**；它也会录到电视、会议、旁人或自言自语。按键输入或显式启用的唤醒交互窗口才可作为面向伙伴的依据，唤醒词也不等于身份认证。**“是否在开会”应优先查应用会话状态**：Windows 有音频会话状态枚举与按进程的会话控制，macOS 可以按应用隔离音频，安卓至少有 `AudioManager.getMode()` 的通话与通话音频模式（很多会议应用不改这个模式，所以它只是弱证据）。**VAD、说话人识别和轮次结束是不同问题**：Silero VAD 可作轻量人声分段，但不判断意图或是否说完；说话人分离即便可流式也不能代替面向伙伴的证据。本地 ASR、判停与对话交接的最新方案见[实时语音调研](local-realtime-speech-research.md)，模型性能需在目标设备实测。

一个必须记住的失败模式：**“静默等于忙碌”是错规则。** 用“笔记本没动就判定为休息”的规则会制造大量假阴性，其中相当一部分来自会议和上课场景。也就是说会议中不用笔记本会被误判为休息，这正是“主动打断会议”的头号误报源。会议判定必须用会议应用与日历，不要用活动量。

### 输入动态：桌面能用，手机基本不能

这是本次调研里最需要提前讲清楚的平台不对称。安卓的无障碍服务只提供界面状态转移事件，**没有按键事件类型**，注入按键则需要签名级权限。手机端只能用文本长度增量、焦点变化和停顿间隔做打字的近似替代，证据强度很弱。

桌面端的可用性和代价：

| 平台 | 键盘与指针时序 | 代价 |
| --- | --- | --- |
| macOS | `CGEvent` 的 event tap，只监听不改写 | 需要输入监控权限；这比全局事件监视器要求的辅助功能权限轻得多，且沙箱可用 |
| Windows | 低层键盘与鼠标钩子或原始输入 | 无权限模型；低层钩子有系统超时摘除风险，回调必须极快返回 |
| Linux X11 | `XRecord`、`XInput2` | 无权限模型 |
| Wayland | 门户远程桌面 + libei | 必须用户交互授权，且接收端生态仍在完善 |
| 浏览器扩展 | 不可得 | 只有 `chrome.idle` 一类的空闲状态 |

可落地的特征按证据强度排序是：**停顿与犹豫的分布 > 退格与撤销率 > 键间时距的变异 > 绝对速度**。一个反直觉但重要的负面结论来自大规模击键日志研究：快慢打字者的**按键按下时长几乎没有差异**，速度信息主要在键间时距里，不在按键时长里。另一个有因果支持的结论是，增加输入延迟会显著提高主观努力与挫败感，但不改变错误率——也就是说打字时序能承载“卡住了或烦了”，不能用来判断“会不会出错”。

“卡住”的最可靠组合仍然是环境事实：连续失败退出码、重复失败的任务切换、撤销循环抬升、长时间不切窗口、输入停顿变长。建议做成连续的分值而不是布尔量，因为“卡住的严重程度”直接对应“她该不该开口”的强度。

隐私侧要写进设计：即使不记录按键内容，持续采集按键时序并上传，在能被推断情绪或健康时仍可能落入特殊类别数据。安全做法是只保留聚合特征（速率、停顿分布、退格率），丢弃原始时间戳与任何键位标识，并在本地完成计算。

### 传感器与生理：只做弱先验

心率变异性在消费级设备上的精度有硬上限：独立验证显示，某腕上设备静息心搏间期序列的偏差很小，但逐对正常心搏区间序列的百分比误差可达三成量级，各条件下采集失败率从百分之几到四成以上，频域功率被系统性低估；某纯摄像头方案的相关系数接近于零。所以结论很明确：**生理通道只能作为“用户最近可能处于高唤醒”的弱先验，用来调语气和主动性，不能进入情绪增量的主计算**，而且它是健康数据，需要单独同意与明确的降级路径。

其余传感器的性价比差别很大。环境光在安卓上不需要权限（但只能读到本机背光传感器的读数，不等于环境照度）；iOS 没有公开的环境光接口。步数与加速度需要活动识别权限，通勤与久坐是强场景先验。电量、充电状态与热状态是零权限信号，而且能解释“为什么现在变慢”“为什么这时候不该打扰”，性价比被低估了。

昼夜与睡眠是最被低估的情绪先验。连续八天的电话日记研究（两个独立样本，分别约两千人与近八百人）显示睡眠时长**单向**预测次日负性情绪，且关系是非线性的：过短与过长都对应更高的次日负性情绪，中间区间最优。工程上完全可以零摩擦采集“本地时刻 + 上次活跃时间 + 会话间隔”作为慢变量，不需要接入任何健康数据。要注意屏幕关闭时长不等于睡眠。

### 日历与外部系统

日历是“该不该打扰”最强的先验，但也是最敏感的一个。只读忙闲与起止时间，不读地点与参与者。安卓上日历权限属于受限权限，需要运行时请求、清晰解释，并提供无权限时的替代路径；苹果侧要用新的完整访问请求并填写对应的用途说明键。

其他高价值且低敏感的通道：通知的生命周期（**划掉是明确的负向信号，未划掉可能只是没看到，不能当成已读**）、即时通讯的等待回复、代码仓库的构建失败回调、终端退出码、IDE 插件的窗口状态、已有的 SSH 会话元数据与家庭网关的实体状态。本项目的显式操作元数据已经在做最后一类，并且它是“卡住”判定里证据等级最高的一类，因为它是环境事实。

## 自触发决策

### 三档动作与延迟的代价

决策的形式化主干来自注意力敏感告警：比较“延迟通知造成的期望损失”与“打断造成的成本”，取小者。加问选项后出现两个阈值，把行为划成静默、提问、直接行动三段。原始论文把用户注意力状态显式列举成十几个情境（专注内容生成或审阅、办公室会议、听演讲、日常交谈、旅行等），这套标签体系可以直接映射成我们的活动判定集合，值得照抄这个做法。

延迟的代价有实证。113 名员工、4803 个忙时段的研究显示，平均忙时长约 43 秒，绝大多数在 1 到 2 分钟内转为空闲，把通知延迟 4 分钟把样本中的忙时告警从 20 条降到 4 条、从 80 条降到 0 条。结论是“延迟几分钟几乎无成本”，因此“先记下来，晚点一起说”是安全默认。

打断的代价同样有实证，而且方向常被搞错。经典实验室实验发现被打断的任务**完成得更快**，但压力、挫折、时间压迫与努力全部显著升高，产出质量没有差异；约 23 到 25 分钟的重返时长来自同一作者的田野观察，不在那篇论文里。恢复成本随介质不同而不同，切到重量级应用远贵于轻量级；约四分之一的中断需要两小时以上才能恢复；被打断前只停留了几分钟的任务有相当比例两小时内不会回到原任务。最后一条的工程含义很直接：**任务边界是最优介入点**，不是任何时刻。

### 效用函数与门限

候选效用可以这样写（每一项都对应一个可观测量）：

```text
EU(speak, o, t) =
      p_needed(o) · [ V_miss(i) + λ · W(i) ]        # 说对了的收益
    − p_unneeded(o) · [ C_interrupt(o,t) + C_privacy(o) ]
    − C_trust(o,t)                                   # 信任负债，带迟滞
    − C_budget(t)                                    # 当日预算与冷却
    + β · EVI(i | o)                                 # “先问一句”的信息价值
    + γ · ρ_boundary(o,t)                            # 处于任务边界 → 打断打折
```

门限形式沿用原始论文的闭式解，再叠加两项工程修正：信任负债带迟滞（信任是非对称的，一次深度错配的损伤大于一次正确修复的收益，恢复需要的时间也长得多），以及预算作为硬约束参与取极而不是惩罚项。

其中“问一句”的信息价值判据来自 Bayesphone：只有当“减少的期望通信成本大于询问成本”时才打断用户去问。这把“要不要问”从直觉变成了可计算量。“提议并等待”的闸门则与厂商的工具风险分级一致：只读与写入、可逆性、所需权限、是否影响外部状态。

### 沉默必须落库

这是本文最想强调的一条工程纪律：**被抑制的候选消息必须落库并可回放**。原因有三：阈值需要数据才能标定；只有评测者能看到系统放弃了什么，才能判断沉默是否正确；只评测“该说时说了”的系统，最终会得到一个什么都想说的代理——业界的评测指南把这称为单边评测，并明确要求同时测“该做的做了”和“不该做的没做”，还要单独关注过度触发与触发不足的平衡。参数（误报代价、漏报代价、各项权重）应当暴露为可调项，并写进现有的理由字段，与当前的 `reason` 设计保持一致。

### 预算、节流与不能归零

节流策略里唯一有随机对照证据的是批处理：每天三次批量的效果量在零点五上下（解锁次数、失控感、走神、压力、日终生产力都有显著改善），每小时批量与对照无差异。更关键的是**完全关掉通知反而升高焦虑与错失感**，并且走神与专注没有改善。沉默会同时产生“更专注”和“焦虑”两种体验，必须个体化。

由此得到三条硬规则：每日主动条数设硬上限；两次之间设冷却；**存在感通道永远保留**，即使完全静默也要有一个不打扰的“我在”。用户对主动介入普遍存在两难：同一件事既被评价为有用又被评价为侵扰，而**先请求许可再开口**是现有研究给出的默认策略；另有一项研究发现，未经请求的主动反馈其适当性评价**低于完全不反馈**。视觉提示被描述为最不干扰的形式，这也正好对应我们现有的 `presence` 语义。

### 与现有接口的关系

现有的 [人格](personality.md) 已经给出 `interaction_mode` 的 `focus` 取值、非主动时保持安静、以及 `participation` 的理由枚举。演进方向不是新增模式，而是把两个东西改造一下：

- **`participation` 从布尔开关改成可调自治参数。** 主动研究里正确的形态是可调自治权限：不是“开或关”，而是一个直接缩放触发门限的连续量。全被动时门限趋近无穷，只保留不打扰的存在感提示；允许旁观时放开到提问；允许参与时才放开到打断与提议。
- **`reason` 从枚举扩成决策记录。** 现在的取值是输出条件不足、陪伴者离开、用户请求、等待用户、各项阈值不足、参与建议。演进后应当能回答“这一条被哪几项证据压住了”，否则无法调阈值。

[屏幕感知与心流判定](screen-perception-and-flow.md) 提出的 `context.screen_state` 与 `modality: "screen"` 可以照搬到环境信号上，成为兄弟字段 `context.ambient_state` 与 `modality: "ambient"`。上报纪律一致：一个节点 ID 由一个进程负责完整写入；只有分级或状态转换才生成事件；数值波动不逐次写事件；心跳不调用模型、不写长期记忆。

## 情感系统：从整句规则到评价向量

### 为什么现在的整句匹配是最短的一块板

现有规则识别若干条明确整句，否定、引用与复杂语义归为中性。这是一个刻意的保守选择，问题是它既没有连续性也没有可校准性：同一句话的语气变化不会被反映，用户改述同类表达就不会被识别，而且系统无法知道自己错在哪。

中文社区有一个现成资源正好补这块：Chinese EmoBank 提供了带效价与唤醒评分的词、短语与单句标注，**并明确区分了否定、程度与情态三类修饰符**，短语条目还标注了修饰符类型。这直接指出当前设计的一个缺陷——中文的情绪极性计算必须处理否定辖域，不能靠整句关键词匹配。大连理工的中文情感词汇本体库提供了两万多词、七大类、强度分级，可作为静态先验的第一层。

### 第一步：在三维之前插一层评价

评价理论给出的最短路径是 Smith 与 Ellsworth 的六维表：愉快性、预期努力、不确定性、注意投入、责任或控制（自他）、情境控制。十五种情绪在这个空间里系统性分离，判别分析的分类率显著高于随机。它的价值在于可以**反向使用**：给定当前的三维状态，算出最匹配的评价向量，看哪一维偏离最大——那就是最能解释此刻状态的维度。

工程形态是把 delta 从直接作用于三维，改成先作用于评价维度、再通过一个标定矩阵投影到三维。这个投影矩阵需要用数据估计，但可以先用中性矩阵跑通。配套改造是把现有规则的整句匹配拆成“评价维度 + 目标词”两段：保留可读性，同时获得可校准性。

离散情绪分类不是这个系统的正确框架。建构论情绪理论的核心主张是日常情绪标签是事后对连续身体感觉的范畴化产物，跨文化研究也发现所谓普遍表达在没有情绪概念提示时并不出现。工程上的对应物是：建模连续状态加少量后验标签，而不是训练细粒度分类器。这与公开基准的结论一致——27 类情绪的平均 F1 明显低于塌缩到 4 类后的结果，而稀有情绪的 F1 为零。

### 第二步：把指数衰减换成状态空间

情绪惯性（自相关）是比半衰期更好的模型：高负性情绪惯性稳定关联低幸福感与抑郁症状，并且能前瞻预测发病；反刍的“反刍思考”面与负性惯性正相关并独立预测严重程度，“反思”面则不然。工程含义是：衰减不应是纯指数，应是一个带回 home base 的过程，带逐维惯性系数，并且能检测反刍。

现成的实现模板有两个：层级化的连续时间 OU 过程，以及状态空间模型加卡尔曼滤波，报告的样本规模在数百人量级，能分别估计惯性矩阵、静息偏置、事件输入矩阵与可控性。两者都可以先用参数固定的滤波器跑通，再逐步估计个体参数。

跨维度耦合要谨慎：生理学上“心理解效价”和“趋近—退缩”不是同一个轴，这提醒我们任何跨维度的经验规则都要先在自己的数据上验证。

**反刍检测器只做打断，不做深挖。** 反刍是抑郁的独立风险因子，而对 AI 伴侣来说“跟我说说你当时在想什么”这类追问恰恰是危险动作。检测到同一主题、负性、自指、跨会话重复时，正确反应是换一个话题或留出空间，而不是往深里问。

### 第三步：home base 用节律而不是健康数据

睡眠时长是情绪的最大单一外部先验（见前文），但接入睡眠意味着新的隐私面。零摩擦的替代方案是用可自采的量构造 home base：本地时刻、上次活跃时间、会话间隔、沉默时长。慢变量只做调制，不参与 delta 的即时计算。

另有一个统计陷阱必须写进设计：初次填量表的人评分系统性更高，尤其在负面体验上。因此**前几天的数据应当降权或单独建模**，不能当作基线。

### 澄清即校准

现有的 invalidate 机制是这套系统里最有价值的未开发资产，但它的定位需要修正。

**澄清不是记忆重固像。** 重固像领域本身在退：多项实验室复现失败，“擦除”在技术上不成立（陈述性知识保留，情绪表达下降），人类研究需要预测误差才能打开不稳定窗。产品承诺应当改为：“这次澄清改变的是我们今后如何理解这段经历，不是删掉它。” UI 上必须明示这一点，否则会制造一个兑现不了的承诺，制造二次伤害。这一点在重固像文献里反而是成立的。

**澄清应该分三类，映射到评价维度：** 方向性澄清改变符号，权重最高；强度澄清只缩小幅度；归因澄清改变评价维度中的责任与控制维，而**不应该改变效价**。这个三分法直接来自六维评价表，是它最有价值的工程回报。

**把澄清当拒绝采样，不要当负标签。** 用户点澄清表达的是“你猜错了”，不是“相反的情绪”。正确处理是把该线索的增量估计向零收缩并扩大不确定性，而不是取反。如果取反，一次“我觉得你不懂我”的澄清就会让模型学到相反方向，这是灾难性错误。观测模型用重尾分布而不是正态，因为澄清是稀疏的、高杠杆的拒绝信号。

**校准指标**应该包括：方向性澄清后符号正确的比例（八周内超过六成）、误极性率（澄清后符号翻转且用户再次澄清的比例，八周内低于百分之十五）、增量幅度的校准曲线斜率（预测幅度对确认幅度，斜率应接近一）、冷启动长度（二十次会话以内）、以及零反馈会话占比（过高说明学得太保守，过低说明模型在硬猜，两种都不健康）。

**主动请求澄清**是有价值但必须克制的：每若干次会话至多一次，必须在一个正向体验之后而不是刚结束负面体验之后，形式是具体多选项并带“都不是”，绝不用开放问句。这里有一条更硬的约束：让用户在情绪诱发任务中持续报告情绪，会**改变其心血管反应模式本身**。换句话说，“你还好吗”这句话会改变用户的生理状态和后续回答。所以不要为了“感知情绪”而频繁询问。

## 表达与关系

### 共情优先于自我表演

一项 N=96 的对照实验给出明确方向：共情性（他向）情绪显著提升用户对代理的喜欢度、可信度、被照顾感与支持感，而**自我导向情绪没有任何效应**。这意味着表达层的预算应向共情倾斜，自身的情绪表演收益很低。

同时不要让代理的情绪完美镜像用户——那会变成单人工回音室。代理需要自己的锚：人格、时间、她自己的叙事，并对用户的变化做出有相位差的反应。

### 亲密的近端机制是感知回应性

亲密感最强的近端预测因子是“感知到的伴侣回应性”，包含理解、确认、关心三个成分；事件日记研究还发现**情绪性自我表露对亲密的预测力强于事实性表露**。这对评测体系的含义很直接：把“她的情绪是否贴切”降为次要指标，把“用户是否感到被理解、被确认、被关心”作为首要指标。后者才是通向亲密的近端路径。

### 习惯化是结构性的，不是措辞问题

对陪伴型代理的 12 周纵向研究显示：关系会渐进形成，但**会话广度随时间下降，中途出现一个明显拐点，多数人互动变少、话题变浅、感觉关系变冷**；同一研究也指出不可预测的事件与技术故障会破坏关系甚至导致终止。由此得出两条：可靠性预算高于情绪表演预算；表达需要慢速演化的多样性预算，不是更复杂，而是更随机、更少重复、更贴合当前具体内容。

### 同步性：做行为，不做生理

人际生理同步与关系质量之间的关联比直觉小得多（元分析中与关系结果的总体关联接近于零且不显著，与表现结果的关联也偏弱）。但**行为同步**对亲社会态度的因果效应不小（元分析中效应量约零点五）。而且实验者盲法是显著调节变量——盲法与明示假设之间差约零点二九个效应量单位。也就是说，想评估同步效果就必须盲法化，否则会系统性高估自己。所以同步应当用语言与行为的时序实现：轮次、停顿、回应延迟、长度匹配，不要指望生理模型。

## 不做什么

这张负面清单比正面建议更值得抄进代码评审。

| 不做的事 | 理由 | 依据强度 |
| --- | --- | --- |
| 训练“识别用户是悲伤还是愤怒”的分类器 | 27 类到 4 类 F1 从 0.46 到 0.69，稀有情绪为 0 | 强 |
| 从面部表情推断情绪 | 跨文化、跨情境、跨人变异极大；方法学上也不支持基本情绪的存在 | 强 |
| 把消费级心率变异性作为情绪依据 | 逐对心搏区间序列误差可达三成量级，采集失败率高，频域功率被系统性低估 | 强 |
| 为了“感知情绪”频繁询问用户 | 询问本身改变生理反应与后续自陈；会强化焦虑循环 | 强 |
| 用模型裁判评估情绪表达质量 | 情感属性恰好是裁判最不可靠且系统性高估的一类；强制单选验证法会选出次优方案 | 强 |
| 把澄清包装成记忆擦除或重固像 | 该领域大面积复现失败，“擦除”在技术上不成立 | 强 |
| 让代理的情绪完美镜像用户 | 单人工回音室；与“代理需要独立锚”的人格一致性目标冲突 | 中强 |
| 对代理的自我导向情绪投入大量设计资源 | 对用户评价无效应，只有共情有效 | 中强 |
| 把“我感觉她是真的在乎我”作为优化目标 | 这是拟人化诱惑的直接指标，应作为风险监控项单独设阈值 | 中强 |
| 对用户做反刍式深挖 | 反刍是独立风险因子；AI 适合做的是打断而不是深化 | 中强 |
| 在情绪增量幅度上做在线强化学习自由探索 | 奖励噪声极大、伤害不对称、与操纵红线冲突 | 推测，风险论证充分 |
| 依赖模型隐式能力做危机检测 | 公开评测显示主流产品在需要“读出字面之外”时显著变差，而情绪推断管线恰恰在做这件事 | 强 |
| 为“企业员工情绪福利”预留接口 | 欧盟人工智能法案禁止在工作场所与教育机构推断情绪（医疗或安全目的除外），禁令自 2025-02-02 起适用；一般职场压力监测不在例外内 | 强 |
| 假设情绪线索可跨个体共用同一映射表 | 同一刺激对不同人的效应方向可能相反 | 中 |
| 用指数半衰期作为唯一衰减模型 | 情绪惯性在秒到天各时间尺度上都稳定关联低幸福感并前瞻预测抑郁 | 强 |
| 只评测“该说时说了” | 单边评测会得到什么都想说的代理；必须同时测过度触发与触发不足 | 强 |

## 安全与合规

必须写进架构而不只是文档的四条。

**危机路径要独立且硬编码。** 心理学会的健康顾问明确要求所有此类应用集成经过测试的危机升级路径，并在检测到风险时给出清晰的人类服务联系方式。不要依赖模型的隐式能力：公开评测显示主流聊天产品在明确说出危机时尚可，在需要读出字面之外时显著变差。这条与情绪推断管线的方向正好相反，因此不能复用。

**不做临床宣称，也不做组织部署路径。** 欧盟法案的禁令只针对工作场所与教育机构，个人自愿使用不在其列，但一旦面向企业员工福利或校园筛查就落入禁止范围。因此不要预留这类接口，这是零成本的架构约束。

**依赖风险要监控而不是优化。** 有厂商已经把情感依赖纳入发布前的基线安全评测，并披露了受影响的用户比例量级；也有研究指出模型在识别正性情绪上远好于负性情绪，因此依赖模型固有能力的安全措施可能失效，需要专门微调或通过设计降低拟人化程度。这直接支持“共情优先、拟人化克制、可靠性优先”的取舍。

**危机与痛苦主题要能被拒绝。** 系统要能说“我帮不上这个”，并且这件事本身不应被计为失败。

## 评测与验收

自触发侧真正该盯的在线代理指标：

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 触发误报率 | 被打断但事后自述当时并未投入的比例 | 第一生死线 |
| 触发漏报率 | 用户明确求助或真实阻塞发生但预算为空的比例 | 越低越好 |
| 每会话打断次数 | 主动打断除以完整会话 | 建议低于 0.3 |
| 段落保全率 | 自然中断与被打断后回到同一任务的比例 | 相对无陪伴者基线 |
| 静默正确率 | 被抑制候选中事后判断“确实该沉默”的比例 | 需要抽样人工复核 |
| 存在感激收率 | 用户后续主动开启对话的比例 | 存在感的价值证明 |

情绪侧：把三个题项（被理解、被确认、被在乎）作为周度问卷，第三项单独作为风险指标监控；配合三个行为代理（会话启动延迟、会话时长、主动开启率）。必须跑同质对照组——一个去除情绪表达层的版本——因为十二周研究里的“关系变冷”未必是习惯化，也可能是需求饱和或技术故障。生理验证只建议在研究阶段用研究级设备做，并且必须盲法化。评测周期按八周设计，因为第 4 到 8 周的拐点只有跑满才知道。

## 扩展路线

1. 先做零成本层：本地时刻、上次活跃、会话间隔、电量与热状态、锁屏与空闲，加上已有的显式操作元数据与终端退出码。以 `context.ambient_state` 上报，只做分级与状态转换事件。
2. 再做会议与通话判定：日历忙闲 + 音频模式 + 会议应用活跃。目标是“绝不打断会议”这一条硬边界能稳定成立。
3. 然后做存在感和三槽批处理，这是唯一有随机对照支持的节流形态，同时把 `participation` 改造成可调自治参数，把 `reason` 扩成决策记录。
4. 情感侧并行推进两条低风险改造：把现有整句规则拆成评价维度加目标词，并用中文情绪资源作为静态先验层；把澄清重写为受控重评级并开始积累校准数据。
5. 引入用户显式开启的语音输入：VAD 分段、实时转写、确认面向伙伴与轮次结束，最后复核访问权并交给对话；不能仅凭人声检测推断用户意愿。路线见[实时语音调研](local-realtime-speech-research.md)。
6. 状态空间与个体惯性参数、主动提问、提议并等待，都排在积累了几周真实接受与拒绝反馈之后再开。

## 未验证与需实测

被广泛转引但查无实据的文献有两处，本文已改用可核实的一手来源：某篇关于“协调式主动”的作者与题名组合未能核实；关于“注意力射线”的说法是作者后期的口头比喻，不是原论文术语，引用时应作为比喻而非论文结论。另有一篇把“建立打断基准”的论文题名与归属有误，其主题其实是相互理解而非打断。

工程侧需要实测的：安卓各厂商对音频播放捕获与无障碍事件的实现差异；桌面低层钩子的超时摘除行为在目标系统版本上的具体表现；语音活动检测在本地语言场景下的误检率；说话人分离模型当前版本的许可与下载门槛；语音活动检测模型仓库内许可标识不一致，商用前需自行确认；日历权限在应用商店审核中的实际口径；微机电音量的绝对值不可用，只能看相对趋势；暂停与犹豫阈值没有通用基线，必须按个人自适应。这些通道的能耗也需要自测，尤其是音频常开的代价。

研究侧：主动发言的时机缺少行业共识，厂商文档只讲何时停下来问人、不讲何时主动开口，这一块仍靠学术基线支撑；可打断性推断的公开研究样本都很小（十余人到数十人量级），跨场景外推要谨慎；关于 2026 年若干预印本提出的动态门限与信任测量，本文只作为背景阅读，未用于任何设计结论；活动分类（会议、游戏、代码）缺少可直接引用的学术文献，目前全部是工程启发式。
